# Модель и контракт для сверки

Глоссарий: **заявка** хранит владельца, ресурс и окончательное решение; **разрешение** возникает при одобрении и имеет независимую пригодность; **срок** — целое количество часов от approved_at; **отзыв** прекращает действие конкретного разрешения и сохраняет историю решения.

| Действие | Владелец alice/bob | Другой сотрудник | carol |
|---|---|---|---|
| Создать заявку | Для себя | Для себя | Для себя |
| Читать заявку | 200 | 403 | 200 для любой |
| Approve/reject | 403 | 403 | Для чужой; своя 403 |
| Revoke (reference) | 403 | 403 | Для чужой approved; своя 403 |
| Проверить доступ | Только свой | Только свой | Любой demo user |

| Состояние решения | Команда | Итог |
|---|---|---|
| pending | approved / rejected от carol для чужой | approved / rejected, 200 |
| approved | approved повторно | approved, 200, без нового эффекта |
| rejected | rejected повторно | rejected, 200 |
| approved / rejected | противоположное | 409, состояние сохранено |
| pending / rejected | revoke | 409 |
| approved, активен/истёк | revoke с причиной | approved + revoked, 200 |
| approved, revoked | revoke с той же/иной причиной | 200 без изменения / 409 |
| approved, revoked | approved повторно | approved + revoked, 200, доступ не оживает |

Статусы разрешения вычисляются: active, expired, revoked; бессрочное legacy-разрешение не становится expired. При обоих признаках запрета доступ отсутствует. Условие reference: существует grant, у которого `revoked_at` отсутствует **и** (`expires_at` отсутствует **или** `now < expires_at`). Состояние заявки approved само по себе не доказывает наличие действующего доступа.

| Метод и путь | Вход | Наблюдаемый результат |
|---|---|---|
| POST /requests | `{"resource":"handbook","hours":1}` | 201, заявка с уникальным id и status=pending |
| GET /requests/{id} | X-User | 200, видимая заявка |
| POST /requests/{id}/decision | `{"decision":"approved"}` или rejected | 200, окончательное решение |
| POST /requests/{id}/revoke | `{"reason":"left team"}` | 200, отзыв; только reference |
| GET /access?user=alice&resource=handbook | X-User | 200, `{"user":"alice","resource":"handbook","allowed":true}` |

Заявка: id, user, resource, hours, status; после одобрения approved_at, для новых reference-разрешений expires_at; после отзыва revoked_at/revoke_reason. Необязательные временные поля до соответствующего события отсутствуют. hours baseline равен 0. Ошибка — JSON; клиент опирается на HTTP-код, не на конкретную формулировку текста.

Ошибки и правила — D12 в [ответах](stakeholder-answers.md). Входы JSON должны быть корректными. На пересечении нескольких ошибок лабораторная не задаёт полный порядок всех проверок; тесты изолируют одно нарушение. Гонки решения/повтора/отзыва защищены одной атомарной критической секцией. Межпроцессная согласованность вне объёма.

## Шаблон самостоятельного анализа

1. Источник / потребность / измеримый результат.
2. AS-IS, TO-BE, граница системы и non-goals.
3. Термины, акторы и доверие.
4. Данные и инварианты.
5. Таблицы ролей, состояний и ошибок.
6. Время, повторы, конкуренция, совместимость.
7. Открытые вопросы и решения владельца.
8. Требования, сценарии, тесты и доказательства.
