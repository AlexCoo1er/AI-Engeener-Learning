# Решения условного заказчика

Откройте после собственных вопросов. Эти ответы — учебный источник договорённостей, а не автоматически выведенные свойства кода.

| ID / вопрос | Согласованное решение |
|---|---|
| D1 Кто действует? | alice и bob — сотрудники, carol — согласующий. carol также может создать собственную заявку. Роль определяется фиксированным адаптером по X-User, никогда заголовком X-Role. |
| D2 Для кого заявка? | Только для самого вызывающего. Ресурсы: handbook и runbook. Переданный JSON не даёт права выбрать другого владельца. |
| D3 Кто видит? | Владелец видит свою заявку, carol — любую. bob не читает заявку alice. |
| D4 Самосогласование? | carol не может approve/reject/revoke собственную заявку. Сотрудники не принимают решений. |
| D5 Повторы и гонки? | Первое решение pending → approved/rejected неизменно. То же решение возвращает 200 без второго эффекта; противоположное — 409. Переход атомарен: при гонке выигрывает одно решение. |
| D6 Исходный срок? | Только baseline: hours отсутствует или 0; разрешение бессрочно. Это правило продукта, не баг. |
| D7 Новый срок? | После temporary-access новые заявки принимают только целое hours 1..24; отсчёт от одобрения. При now >= expires_at доступа нет. Повтор approved не продлевает срок. |
| D8 Совместимость? | Ранее одобренное бессрочное разрешение остаётся бессрочным после смены политики. Старую pending с hours=0 можно отклонить, но одобрение возвращает 400; пользователь создаёт новую заявку с допустимым сроком. Для этой миграции тест переключает политику в одном хранилище; перезапуск сервера очищает память. |
| D9 Отзыв? | Только после одобрения, в том числе уже истёкшего разрешения. Причина обязательна, пробелы по краям удаляются. Решение остаётся approved, записываются revoked_at/revoke_reason. Повтор той же причины — 200 без нового времени; другой — 409. |
| D10 Несколько заявок? | Доступ есть, если хотя бы одно разрешение пользователя к ресурсу активно. Отзыв одной заявки не отзывает остальные. |
| D11 Время и история? | Серверные управляемые часы; тесты не ждут sleep. Повтор approve не меняет approved_at/expires_at и никогда не восстанавливает отозванное разрешение. |
| D12 Ошибки? | 201 создание; 200 чтение/проверка/решение/отзыв; 400 неверные поля; 401 неизвестная или отсутствующая demo identity; 403 запрет роли/владения; 404 неизвестная заявка; 409 конфликт состояния/решения. Неизвестный user в проверке доступа — 400. |

Предел доверия: X-User — только локальный тестовый адаптер. Наличие curl-примера не делает его аутентификацией production. Сервер слушает loopback, хранит данные в памяти одного процесса, после рестарта всё исчезает.

Продуктовый владелец принимает смысл D1–D12. Разработчик обеспечивает поведение. CLI проверяет структуру, но не выбирает бизнес-правила и не запускает тесты приложения.
