## Context
Бессрочные новые разрешения превышают потребность команды; N3/D7–D8 требуют срока и совместимости.

## Goals / Non-Goals
Наблюдаемый контракт описан дельтами. Только локальная память, Go или Java; IAM, БД, UI и продление вне объёма.

## Decisions
Используем управляемые серверные часы и храним expires_at при первом одобрении. Политика меняется без пересоздания исторических grants; не выводим срок из времени запуска. Одно хранилище и критическая секция сохраняют атомарность.

## Risks / Trade-offs
Синтаксически корректная дельта может потерять сценарии. Поэтому MODIFIED содержит весь итоговый блок, а архивирование проверяется на временной копии с сравнением final snapshot. In-memory не даёт долговечности после рестарта.

## Migration Plan
Сохранить approved grants без expires_at. Для новых заявок требовать срок; старую pending hours=0 отклонить или создать заново с hours 1..24. Откат спецификаций не отменяет уже выданные данные автоматически.
