## Найденные и устранённые несогласованности

- Мобильная шапка нового модуля переполнялась: исправлены локальные стили; 390px перепроверены.
- Успешный сценарий создания, унаследованный от baseline, в финальном контракте не указывал обязательный hours. Во временной дельте и итоговой спеке сохранено имя сценария, а вход уточнён до hours1. Остальные унаследованные входы также проверены. Пример добавлен в теорию: сохранять гарантию не означает буквально оставлять устаревшие входы.
- Проверка отсутствующего request id при принятии/отзыве решения приведена к согласованному 404 для известной личности, с Go/Java регрессионными проверками.

## Ограничение общего Java-прогона

Неизменённый `examples/java/m16-voice/src/test/java/course/m16voice/VoiceTest.java`, тест `turnStreamsBySentence`, дважды не прошёл wall-clock assertion: TTS 151 и 171 мс при ожидаемых ≈125 мс. Прогон останавливается до нового модуля. Отдельный реакторный прогон `m17-sdd` успешен. Голосовой код и его допуски не изменялись ради этой задачи; общий Java-набор не объявляется зелёным.

## Граница лабораторной

Память одного процесса, loopback, фиксированные демонстрационные личности X-User. Нет production IAM, SSO, реальной выдачи прав, долговечности или межпроцессных гарантий. Изменение политики проверяется в одном экземпляре сервиса с управляемыми часами; перезапуск HTTP-сервера не является миграцией данных. Продление — аналитическое упражнение, в reference оно не реализовано.
